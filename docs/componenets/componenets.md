===================================================

VANGUARD

COMPONENTS

===================================================

PHILOSOPHY

Every component has ONE primary
responsibility.

Components should:

- Be simple.
- Be transparent.
- Have clearly defined boundaries.
- Perform ONE primary task extremely well.

If a component begins taking on multiple
major responsibilities, it should be
re-evaluated or split into multiple
components.

===================================================

TIER 1 COMPONENTS (REQUIRED)

===================================================


1.) HARDWARE MANAGER

-----------------------------------------

Primary Responsibility:

Understand Machines.

-----------------------------------------

Responsible For:

- Detecting Hardware.
- Reporting Hardware Information.
- Detecting Hardware Changes.
- Reporting Hardware Utilization.

-----------------------------------------

Examples:

- CPU Information
- GPU Information
- RAM Information
- Storage Information
- Operating System Information
- Hardware Changes

-----------------------------------------


2.) RECOMMENDATION ENGINE

-----------------------------------------

Primary Responsibility:

Understand Users.

-----------------------------------------

Responsible For:

- Recommending Models.
- Recommending Settings.
- Recommending Performance Profiles.
- Recommending Storage Profiles.
- Providing Intelligent Recommendations.

-----------------------------------------

Examples:

- Coding Models
- General Use Models
- High Performance Models
- High Quality Models

-----------------------------------------

-----------------------------------------

Primary Responsibility:

Understand Information.

-----------------------------------------

  Occur.

-----------------------------------------

Examples:

- Hardware Information
- Performance Information

- Notifications

-----------------------------------------

-----------------------------------------

Responsible For:

TIER 2 COMPONENTS (IMPORTANT)

===================================================


6.) DOWNLOAD MANAGER

-----------------------------------------

Primary Responsibility:

Understand Downloads.

-----------------------------------------

Responsible For:

- Downloading Models.
- Showing Download Progress.
- Pausing Downloads.
- Resuming Downloads.
- Canceling Downloads.
- Managing Download States.

-----------------------------------------

Examples:

- Download Progress
- Paused Downloads
- Multiple Downloads

-----------------------------------------


7.) STORAGE MANAGER

-----------------------------------------

Primary Responsibility:

Understand Storage.

-----------------------------------------

Responsible For:

- Storage Estimates.
- Storage Warnings.
- Storage Utilization Information.
- Providing Storage Recommendations.

-----------------------------------------

Examples:

- Remaining Storage.
- Low Storage Warnings.
- Model Storage Requirements.

-----------------------------------------

NOTE:

Storage recommendations should be
percentage based whenever possible.

Recommendations should always be
preferred over restrictions.


-----------------------------------------


8.) SETTINGS MANAGER

-----------------------------------------

Primary Responsibility:

Understand User Preferences.

-----------------------------------------

Responsible For:

- Managing User Preferences.
- Managing Application Preferences.
- Managing Performance Preferences.
- Managing UI Preferences.

-----------------------------------------

Examples:

- Beginner Preferences
- Advanced Preferences
- UI Customization
- Performance Goals

-----------------------------------------



9.) UPDATE MANAGER

-----------------------------------------

Primary Responsibility:

Understand Updates.

-----------------------------------------

Responsible For:

- Managing Update Notifications.
- Managing Available Updates.
- Informing Users Of Changes.

-----------------------------------------

Examples:

- Model Updates
- Vanguard Updates
- Version Changes

-----------------------------------------

NOTE:

Vanguard should NEVER automatically
perform important updates without
user permission.

Users should ALWAYS have the final
decision.


-----------------------------------------


10.) DOCUMENTATION MANAGER

-----------------------------------------

Primary Responsibility:

Improve Understanding.

-----------------------------------------

Responsible For:

- Explaining Concepts.
- Providing Documentation.
- Providing Beginner Friendly
  Explanations.
- Teaching Without Overwhelming.

-----------------------------------------

Examples:

- Tok/sec
- VRAM
- Quantization
- Performance Profiles

-----------------------------------------

NOTE:

Documentation should be:

- Beginner Friendly.
- Transparent.
- Easily Accessible.

Advanced users should never feel
overwhelmed by unnecessary
documentation.
